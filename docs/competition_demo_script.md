# KB TradeGuard AI · 3분 시연 스크립트

## 시연 원칙

- 메인 시나리오는 `② O/A 90일 고위험 수출`을 사용한다.
- 첫 화면에서 기능 목록을 설명하기보다 거래 의사결정 문제를 먼저 제시한다.
- 판정은 승인·거절이 아니라 사전진단 상태라는 점을 유지한다.
- 각 주장 뒤에는 화면의 Finding ID, RiskSignal ID, Calculation ID, Evidence ID 또는 Case hash를 보여준다.
- Live AI는 선택형 후단 설명 기능으로만 소개하며 API 크레딧이 없는 제출 환경에서는 실제 호출하지 않는다.

## 0:00–0:25 · 문제와 제품 정의

발표 문장:

> 중소 수출기업은 신규 해외 바이어와 거래할 때 계약서, 결제조건, 문서 불일치, 국가위험, 환노출과 선적 전 자금부담을 각각 따로 검토합니다. KB TradeGuard AI는 이를 `기업 × 거래 × 바이어 × 국가 × 계약조건` 단위로 결합해, 거래 확정 전에 무엇을 보완하고 어떤 금융·보험·보증 상담을 준비해야 하는지 근거와 함께 제시합니다.

화면:

- Hero 영역
- 결정론적 판단 기준
- 근거 ID 연결
- Human Review Overlay
- 감사 가능한 산출물

## 0:25–0:45 · 거래 입력

1. 사이드바에서 `② O/A 90일 고위험 수출`이 선택되어 있는지 확인한다.
2. 시나리오 설명에서 다음 세 항목을 짚는다.
   - 신규 바이어와 O/A 90일
   - 문서 통화·금액 불일치
   - 선적 전 자금수요와 상담 후보
3. `5단계 거래 사전진단 실행`을 누른다.

발표 문장:

> 실제 고객정보를 공개하지 않기 위해 검수된 합성 Gold Scenario를 사용하며, 업로드 모드에서는 동일한 Pydantic 계약을 만족하는 단일 거래 JSON Package만 받습니다. 누락된 값은 자동으로 채우지 않습니다.

## 0:45–1:20 · 통합 판정과 5단계 Trace

화면:

- 상단 Verdict Banner
- Critical·High, 누락정보, 상담 후보, Pipeline 지표
- 5단계 Stepper
- `① 요약` 탭의 가장 먼저 볼 위험과 첫 번째 실행 행동

발표 문장:

> 이 거래는 승인이나 거절이 아니라 `거래 확정 전 조건 보완 필요`로 분류됩니다. 문서 사전검사, 문서 간 정합성, 재무감내, 상담 후보 매칭과 통합 Brief가 순서대로 실행되며 각 단계의 입력·출력 Case hash와 생성 레코드를 남깁니다.

## 1:20–1:55 · 위험과 근거

1. `② 위험·근거` 탭을 연다.
2. 상위 Concern과 심각도 분포를 보여준다.
3. Concern의 Reference ID를 보여준다.
4. `③ 문서` 탭에서 조항 Finding과 전문가 역할을 보여준다.

발표 문장:

> 시스템은 문서의 전체 의미를 자율적으로 법률 해석하지 않습니다. 사람이 검토해 구조화한 필드에 프로젝트 룰을 적용하고, 각 Finding을 Evidence와 Rule ID에 연결합니다. Critical 또는 High Finding은 법무·은행·물류 등 지정 전문가 검토 대상으로 남습니다.

## 1:55–2:25 · 재무감내와 상담 후보

1. `④ 재무` 탭에서 거래 원화환산액, 식별 유동성, 보호되지 않은 노출과 선적 전 필요자금을 비교한다.
2. `⑤ 상담 후보` 탭에서 KB·K-SURE 공개 상품·서비스 상담 후보를 보여준다.

발표 문장:

> 재무 계산은 AI가 생성하지 않고 입력 재무 Snapshot과 명시적 환율·보호비율을 사용한 결정론적 Calculation으로 수행됩니다. 상품 결과도 승인이나 적격 확정이 아니라, 현재 거래 목적과 필요에 맞춰 상담할 후보와 미확인 조건을 제시하는 수준입니다.

## 2:25–2:48 · 실행계획

1. `⑥ 실행계획` 탭을 연다.
2. 담당자, 선행 Action, 필요서류와 RiskSignal 연결을 보여준다.

발표 문장:

> 분석 결과를 경고 목록으로 끝내지 않고, 어떤 자료를 누가 먼저 확인해야 다음 상담과 거래조건 협의가 가능한지 의존관계가 있는 Action Plan으로 변환합니다.

## 2:48–3:00 · 감사 산출물과 마무리

1. `⑦ 감사·다운로드` 탭을 연다.
2. Input Package hash, Input Case hash, Output Case hash를 보여준다.
3. Markdown, Decision Brief JSON, 감사 ZIP과 발표 Snapshot 다운로드 버튼을 보여준다.

마무리 문장:

> KB TradeGuard AI의 차별점은 AI가 금융 판단을 대신한다는 데 있지 않습니다. 결정론적 룰과 계산, 근거 ID, Human Review와 감사 가능한 산출물을 하나의 무역금융 업무흐름으로 연결해, 중소기업이 은행과 보험기관에 더 준비된 상태로 상담하도록 돕는 데 있습니다.

## 선택형 Live AI 설명

시간이 남을 때만 `⑧ 선택형 Live AI` 탭을 보여준다.

발표 문장:

> Live AI Adapter도 구현했지만 기본값은 OFF입니다. 완료된 Brief와 허용된 Reference ID만 모델에 전달하고, 모든 inline citation이 검증을 통과한 답변만 표시합니다. API 장애나 크레딧 부재와 무관하게 전체 사전진단·보고서·감사 기능은 독립적으로 동작합니다.

## 필수 캡처 목록

1. Landing Hero + O/A 시나리오 카드
2. Verdict Banner + 5개 KPI + 5단계 Stepper
3. 요약 탭의 Top Concern + First Action
4. 위험·근거 탭의 Concern 표와 Reference ID
5. 문서 탭의 Finding·전문가 검토 표
6. 재무 탭의 거래 규모·유동성 비교
7. 상담 후보 탭
8. 실행계획 탭의 의존관계
9. 감사·다운로드 탭의 세 가지 hash와 다운로드 버튼
10. Live AI OFF 또는 Grounding Packet 화면

## 제출 시 표현

사용 가능:

- 결정론적 거래 사전진단
- 근거 기반 상담 준비
- 상담 후보
- 전문가 확인 선행 필요
- 거래 확정 전 조건 보완 필요
- 현재 검토자료상 중대한 경보 없음

사용 금지:

- KB 승인 완료
- 대출 가능 확정
- 보험 인수 확정
- 제재 해소 완료
- 안전한 거래 인증
- 법률적으로 유효함
- 실행 금리 또는 한도 보장
